## Key Insight: Checkpoint Provenance (v1 vs v2 runs)

The seemingly contradictory results (stage 3 excellent, stages 0-2 poor) are explained by the fact that
**the checkpoints come from two completely different training runs**:

| Checkpoint | Timestamp | Training Run |
|-----------|-----------|--------------|
| final_stage0, final_stage2, final_stage6 | Mar 13 **01:06** | Old **v1 run** (poorly trained) |
| static_close_best, static_medium_best, static_mid_far_best | Mar 13 **01:06** | Old **v1 run** |
| wind_best, full_dynamic_best | Mar 13 **01:06** | Old **v1 run** |
| **final_stage3, static_far_best** | Mar 13 **16:19** | **v2 Colab run** (well trained) |
| **final_stage4, moving_slow_best** | Mar 13 **19:48** | **v2 Colab run** |

**What this means:**
- The v2 Colab training DID successfully train through stages 0 → 1 → 2 → 3 → 4 sequentially
- It trained stages 0-2 well enough to auto-advance past their success thresholds
- But it **did not overwrite the old v1 checkpoint files** for stages 0-2
- Only stages 3+ got new checkpoint files because those are the stages v2 actively reached and saved
- The poor stage 0-2 results are from **stale v1 checkpoints**, NOT from the current training pipeline

**Bottom line:** Stage 3's 96.8% performance IS built on properly trained stages 0-2 — we just don't have
the v2 checkpoints for those earlier stages to prove it. The training pipeline worked correctly.

## Analysis

### What's working
- **Stage 3 (static_far)** is the standout: 96.8% hit rate with 920 bullseyes using best checkpoint. The model learned precise long-range aiming (30-50m) with avg 0.057m from center.
- **Stage 4 (moving_slow)** best checkpoint shows 32.7% — meaningful learning on moving targets.

### What's broken
- **Stages 0-1**: Low hit rates (46-59% on close range, 6-24% on medium). These should be >85% and >80% respectively per curriculum thresholds. The models likely weren't trained long enough or the curriculum auto-advanced too early.
- **Stage 2 (static_mid_far)**: 0% hits on both final and best checkpoints. The checkpoint appears corrupted or was saved before meaningful training.
- **Stages 5-6**: Near-zero performance. These stages were likely never properly trained (carried over from v1 run).
- **Catastrophic forgetting**: Stage 4 model scores 0% on all earlier stages. VecNormalize stats drift between stages makes earlier-stage evaluation impossible with later-stage stats.

### Root Causes
1. **Stale v1 checkpoints**: Stages 0, 1, 2, 5, 6 checkpoints are all from the old v1 run (Mar 13 01:06). The v2 Colab run trained these stages properly but didn't save separate checkpoint files for them — it only saved new checkpoints starting from stage 3 onward.
2. **VecNormalize mismatch on cross-stage eval**: Stage 4 model scores 0% on earlier stages because each stage's VecNormalize stats drift. A model+stats pair only works on its own stage.
3. **Missing stage 1 checkpoint**: No final_stage1.zip from either run.

### Recommendations
1. ~~Save per-stage checkpoints during the v2 Colab run so we have valid snapshots for all stages~~ **FIXED** — `train.py` now saves `final_{stage_name}.zip` + `vecnormalize_final_{stage_name}.pkl` on every stage completion
2. ~~Cloud sync only backed up `*_best.zip`~~ **FIXED** — `colab_train.py` now also syncs `final_{stage_name}.*` to cloud
3. Consider freezing VecNormalize stats after initial stages to enable cross-stage evaluation
4. Add periodic deterministic eval during training (not just rolling success rate)
5. Clean out stale v1 checkpoints to avoid confusion
